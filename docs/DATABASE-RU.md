# SQLite в Huawei SMS

Huawei SMS хранит рабочие данные в одной базе SQLite.

По умолчанию:

```text
data/sms.sqlite
```

Готовая база в репозиторий не входит.

## 1. Создание новой базы

Новая установка не требует `schema.sql` и ручного импорта SQL.

При первом вызове `db()` Huawei SMS:

1. создаёт каталог базы, если его ещё нет и процесс имеет право записи;
2. открывает SQLite через PDO;
3. включает рабочие PRAGMA;
4. создаёт отсутствующие таблицы и индексы;
5. применяет встроенные преобразования старых вариантов схемы;
6. выставляет текущий маркер:

```text
PRAGMA user_version = 5
```

`db()` вызывается веб-интерфейсом, `cron/poll.php`, `preflight` и `migrate.php`, поэтому отдельный шаг «создать базу» для новой установки не нужен.

## 2. Почему нет `schema.sql`

Актуальная схема описана в PHP-коде `init.php`.

Отдельная копия `database/schema.sql` намеренно не используется. Иначе пришлось бы синхронно поддерживать два источника схемы, которые со временем могут разойтись.

## 3. Основные PRAGMA

При открытии соединения включаются:

```text
PRAGMA journal_mode = WAL
PRAGMA synchronous = NORMAL
PRAGMA busy_timeout = 5000
PRAGMA foreign_keys = ON
```

WAL позволяет веб-интерфейсу и периодическому `cron/poll.php` работать с одной базой без постоянной взаимной блокировки чтения и записи.

`busy_timeout` даёт короткой конкурирующей операции время завершиться вместо мгновенной ошибки `database is locked`.

## 4. Защита от запуска старого кода на будущей базе

Перед изменением схемы Huawei SMS читает:

```text
PRAGMA user_version
```

Если маркер больше `5`, версия 1.0.0 прекращает работу с ошибкой.

Это защищает базу от ситуации, когда будущая версия уже создала новую схему, а администратор случайно запустил поверх неё старый код.

Старый Huawei SMS не понижает более новый `user_version` до 5.

## 5. Таблица `sms`

Хранит входящие и исходящие сообщения.

Основные поля:

| Поле | Назначение |
| --- | --- |
| `id` | локальный номер записи |
| `modem_index` | индекс SMS в Huawei, если известен |
| `direction` | `inbox` или `outbox` |
| `phone` | номер |
| `sms_date` | дата сообщения |
| `content` | текст |
| `smstat` | состояние сообщения по данным Huawei |
| `deleted_from_modem` | удалось ли удалить модемную копию |
| `notified` | завершена ли обычная доставка уведомления о входящем SMS |
| `source_fingerprint` | устойчивый отпечаток сообщения |
| `created_at` | время появления локальной записи |

## 6. Почему `modem_index` не уникален

Huawei может повторно использовать индекс после удаления сообщения.

Поэтому старый уникальный индекс по `modem_index` удаляется.

Для дедупликации применяется:

```text
source_fingerprint
```

Базовый отпечаток строится из направления, номера, даты и текста. Если два разных сообщения совпали по всем этим полям, индекс Huawei используется как дополнительный признак различия. Сам по себе индекс Huawei уникальным идентификатором не считается, потому что модем может использовать его повторно после удаления старого SMS.

На `source_fingerprint` создаётся частичный уникальный индекс для непустых значений.

## 7. Входящие SMS

Обычное входящее SMS сначала сохраняется локально, затем Huawei SMS пытается удалить его из модема.

Если удаление успешно:

```text
deleted_from_modem = 1
```

Если удаление не удалось:

```text
deleted_from_modem = 0
```

При следующем цикле опроса Huawei снова отдаст то же сообщение. Благодаря `source_fingerprint` новая локальная копия не создаётся, а удаление можно повторить.

Если общий переключатель уведомлений выключен в момент импорта, SMS всё равно сохраняется, но сразу получает `notified = 1`. Это сознательно отключает будущую рассылку именно этого сообщения: включение уведомлений позже не отправляет старый накопившийся хвост. Если уведомления включены, но отдельный канал временно недоступен, его неудачная доставка, наоборот, сохраняется и может быть повторена.

## 8. Командные SMS

SMS-команда с доверенного номера тоже сохраняется в `sms` как входящее сообщение.

Для неё сразу используется:

```text
notified = 1
```

Это означает только то, что обычное уведомление «Новое SMS» не требуется. Результат команды имеет собственный ответ по SMS.

История самого выполнения находится отдельно в `sms_command_history`.

## 9. Локальный список блокировки

Сообщения, которые администратор сознательно отбрасывает через локальный список блокировки, являются исключением из общей истории.

Они:

- удаляются из Huawei;
- записываются в `logs/spam.log`;
- не создают запись в `sms`.

## 10. Исходящие SMS

При отправке из Huawei SMS запись создаётся в SQLite сразу после подтверждения Huawei API.

В этот момент `modem_index` ещё неизвестен. Локальная запись получает уникальный временный `source_fingerprint`, поэтому две одинаковые отправки одному номеру в одну секунду сохраняются как два отдельных SMS.

Когда следующий цикл читает папку исходящих Huawei, система пытается найти локальное SMS с тем же номером и текстом и временем в пределах приблизительно двух минут.

Если запись найдена:

- ей назначается `modem_index`;
- дата уточняется по Huawei;
- записывается новый `source_fingerprint`;
- перед удалением модемной копии `deleted_from_modem` становится `0`;
- после успешного удаления становится `1`.

Если подходящей локальной записи нет, создаётся новое исходящее SMS. Так сохраняются сообщения, отправленные другим интерфейсом Huawei.

## 11. Таблица `sms_notification_deliveries`

Хранит доставку обычного уведомления о новом входящем SMS отдельно по каждому каналу.

Ключ:

```text
source_fingerprint + channel
```

Поля состояния:

```text
pending
sent
failed
```

Также хранятся число попыток, последняя ошибка и время обновления.

Если Telegram доставил сообщение, а Matrix нет, успешный Telegram повторяться не должен. Следующая попытка относится только к недоставленному каналу.

После того как все текущие включённые каналы доставили уведомление, у SMS ставится:

```text
notified = 1
```

## 12. Таблица `sms_command_history`

Хранит идемпотентность и результат SMS-команд.

Ключ:

```text
fingerprint
```

Основные поля:

| Поле | Назначение |
| --- | --- |
| `command_type` | тип команды |
| `phone` | доверенный номер |
| `status` | состояние обработки |
| `attempts` | число попыток начать обработку |
| `request_id` | идентификатор запуска внешнего обработчика |
| `result_status` | подробный итог |
| `reply_sent` | весь ответ отправлен |
| `reply_text` | полный готовый ответ |
| `reply_chunks_json` | сохранённые части ответа |
| `reply_next_chunk` | следующая недоставленная часть |
| `reply_attempts` | число попыток отправки ответа |
| `reply_last_attempt_at` | время последней попытки |
| `finished_at` | время завершения обработки |

Состояния поля `status`:

```text
processing
completed
queued
failed
```

`queued` сохраняется только для совместимости со старыми данными. Отдельной очереди выполнения в версии 1.0.0 нет.

## 13. Что происходит после аварии команды

Если процесс завершился при `processing`, запись остаётся в базе.

Внешний обработчик автоматически второй раз не запускается после истечения защитного времени, потому что первое действие могло реально выполниться.

Готовый ответ, наоборот, можно безопасно отправлять повторно: его части уже сохранены в `reply_chunks_json`.

## 14. Таблица `login_attempts`

Хранит ограничение неудачных входов.

Ключ строится из IP клиента.

Счётчик обновляется внутри короткой `BEGIN IMMEDIATE` транзакции, чтобы параллельные запросы не потеряли одну из попыток.

Старые записи очищаются согласно `login_attempt_retention_days`.

## 15. Таблица `app_state`

Небольшое хранилище состояния вида:

```text
key → value
```

Там находятся, в частности:

- состояние доступности модема;
- счётчики отказов и восстановлений;
- время начала недоступности;
- состояние плановой перезагрузки;
- режим обслуживания;
- состояние доставки событий модема;
- служебные ограничения частоты журналирования;
- использованные интервалы TOTP для защиты от повтора кода.

Такое состояние переживает перезапуск PHP и systemd.

## 16. Файловые блокировки

Конкуренция регулируется не только SQLite.

По умолчанию используются:

```text
data/sms.sqlite.bootstrap.lock
data/sync.lock
data/modem-api.lock
data/script-commands.lock
```

`sms.sqlite.bootstrap.lock` используется только во время создания или обновления структуры базы. Он не даёт веб-запросу и `cron/poll.php` одновременно выполнять одни и те же изменения схемы на новой установке.

`sync.lock` не позволяет одновременно запустить две синхронизации SMS.

`modem-api.lock` согласует изменяющие запросы к Huawei.

`script-commands.lock` ограничивает параллельное выполнение внешних команд.

## 17. `bin/migrate.php`

Команда:

```bash
sudo -u www-data php /srv/huawei-sms/bin/migrate.php
```

открывает базу через тот же `db()` и выводит:

- путь;
- результат `PRAGMA quick_check`;
- текущий маркер схемы.

Она полезна при проверке обновления существующей установки.

Для чистой установки запускать её отдельно не обязательно.

## 18. `bin/preflight.php`

`preflight` также открывает SQLite через основной механизм и проверяет:

```text
PRAGMA quick_check
PRAGMA user_version
```

Его нужно запускать от рабочего пользователя приложения, а не от root.

## 19. Проверка базы вручную

Если установлен `sqlite3`:

```bash
sqlite3 /srv/huawei-sms/data/sms.sqlite 'PRAGMA integrity_check;'
sqlite3 /srv/huawei-sms/data/sms.sqlite 'PRAGMA foreign_key_check;'
sqlite3 /srv/huawei-sms/data/sms.sqlite 'PRAGMA user_version;'
```

Ожидаемый `integrity_check`:

```text
ok
```

## 20. Резервное копирование

При активном WAL не делайте резервную копию простым `cp` одного `sms.sqlite`.

Используйте SQLite backup API, например через `sqlite3`:

```bash
mkdir -p /root/huawei-sms-backup
chmod 0700 /root/huawei-sms-backup
sqlite3 /srv/huawei-sms/data/sms.sqlite \
  ".backup '/root/huawei-sms-backup/sms.sqlite'"
chmod 0600 /root/huawei-sms-backup/sms.sqlite
```

Затем:

```bash
sqlite3 /root/huawei-sms-backup/sms.sqlite 'PRAGMA integrity_check;'
```

## 21. Что нужно сохранять для восстановления

Минимально:

```text
data/sms.sqlite
config.local.php
```

Если используются:

```text
commands.local.php
blocklist.local.php
scripts.local/
secrets/
```

их тоже нужно резервировать.

Журналы не обязательны для запуска, но могут быть полезны при расследовании проблем.
