# SMS-команды

Huawei SMS может выполнять команды, полученные обычным SMS с доверенного номера.

Механизм команд отделён от веб-интерфейса. Он работает внутри `cron/poll.php` при разборе входящих сообщений Huawei.

## 1. Доверенные номера

Команды выполняются только с номеров, перечисленных в:

```php
'sms_commands' => [
    'enabled' => true,
    'trusted_phones' => [
        '+79000000000',
        '+358401234567',
    ],
],
```

Для международных номеров используйте формат с `+` и цифрами.

Для совместимости со старыми российскими настройками в `trusted_phones` допускается запись вида:

```text
89000000000
```

Она сравнивается с `+79000000000`.

Эта совместимость применяется только к доверенным номерам без ведущего `+`. Huawei SMS не пытается угадывать страну у полноценного международного номера.

## 2. Что считается командой

Первое слово SMS — имя команды или один из её алиасов.

Например:

```text
Пинг 192.0.2.10
```

разбирается как:

```text
команда: Пинг
аргумент: 192.0.2.10
```

Регистр команды не учитывается.

Лишние пробельные символы между словами сворачиваются.

Кавычки не создают один составной аргумент. Сообщение:

```text
Команда "два слова"
```

по-прежнему разбирается как несколько токенов и обычно будет отвергнуто проверкой аргументов.

## 3. Штатные команды

### Пинг

```text
Пинг <IPv4 или имя>
```

Пример:

```text
Пинг example.org
```

Также принимается:

```text
ping example.org
```

Команда использует `scripts/network-check.py` и выполняет ICMP-проверку.

В версии 1.0.0 штатный скрипт Пинг поддерживает IPv4 и DNS-имена. IPv6 намеренно не заявлен.

### Порт

```text
Порт <IPv4 или имя> <1–65535>
```

Пример:

```text
Порт example.org 443
```

Алиасы:

```text
port
nc
```

Скрипт пытается установить TCP-соединение с указанным узлом и портом.

### Модем

```text
Модем
```

Алиас:

```text
lte
```

Команда запускает `scripts/modem-health.sh`.

Она обращается к Huawei HiLink API и, если данные доступны, показывает:

- доступность модема;
- состояние мобильного соединения;
- оператора;
- тип сети;
- WAN IP;
- индикатор сигнала;
- RSRP;
- RSRQ;
- SINR;
- RSSI;
- число непрочитанных SMS;
- время полного цикла API-проверки.

Основной обязательный запрос для успешной диагностики — `/api/monitoring/status`. Если он не получен, команда завершается ошибкой. Отсутствие необязательных данных сигнала, оператора или счётчика SMS отмечается отдельно и не превращает всю диагностику в ложный успех.

## 4. Помощь

Встроенная команда HELP настраивается параметром:

```php
'help_commands' => [
    'помощь',
    'команды',
    'help',
],
```

Она выводит список включённых зарегистрированных команд и их `usage`.

HELP не запускает внешний скрипт.

## 5. Локальные команды

Пользовательские команды описываются в:

```text
commands.local.php
```

Их обработчики обычно находятся в:

```text
scripts.local/
```

Локальные команды дополняют штатные. Если локальная запись имеет тот же `script_command`, что и штатная, она заменяет соответствующую штатную запись.

Полное руководство: [PLUGINS-RU.md](PLUGINS-RU.md).

## 6. Что происходит с командным SMS

После распознавания команды Huawei SMS создаёт отпечаток из нормализованного номера, даты, текста и индекса сообщения Huawei, затем проверяет `sms_command_history`.

Если это новое сообщение:

1. создаётся запись `processing`;
2. выполняется HELP или внешний обработчик;
3. сохраняется итоговый статус;
4. готовится ответ;
5. выполняется попытка отправить ответ по SMS;
6. само входящее командное SMS сохраняется в общей истории;
7. после обработки оно удаляется из памяти Huawei.

Для командного SMS обычное уведомление «Новое SMS» не отправляется.

## 7. Защита от повторного запуска

Отпечаток команды строится из:

- нормализованного номера;
- даты входящего SMS;
- нормализованного текста команды;
- индекса сообщения Huawei (`modem_index`).

Для совместимости с историей старых установок при поиске уже обработанной команды дополнительно проверяется прежний вариант отпечатка без `modem_index`. Для новых записей используется полный отпечаток с индексом Huawei.

Если Huawei повторно отдаст уже завершённое командное SMS, обработчик второй раз не запускается.

Если ответ ранее не удалось отправить, Huawei SMS повторяет только отправку сохранённого ответа.

## 8. Авария во время внешней команды

Самая опасная ситуация — процесс PHP завершился после запуска внешнего действия, но до сохранения результата.

Например, плагин мог успеть выполнить:

```text
перезапуск службы
```

а PHP был убит сразу после этого.

При следующем цикле опроса в базе останется состояние `processing`.

Пока запись ещё свежая, Huawei SMS ждёт и не удаляет исходное SMS.

После истечения защитного времени система переводит команду в неопределённое завершение и **не запускает внешний скрипт повторно**. Пользователь получает ответ о том, что автоматический повтор заблокирован.

Такой подход безопаснее, чем случайно дважды выполнить перезагрузку, удаление, переключение или другое действие с побочным эффектом.

## 9. Повтор отправки ответа

Готовый ответ хранится в `sms_command_history`.

Если отправка через Huawei не удалась, параметры:

```php
'reply_retry_max_attempts' => 10,
'reply_retry_interval_seconds' => 60,
```

определяют дальнейшие попытки.

Повтор выполняется в следующих циклах `cron/poll.php` и не запускает саму команду ещё раз.

## 10. Длинный ответ

Текст ответа сначала ограничивается `max_reply_chars` конкретной команды.

Затем он делится на части по:

```php
'reply_chunk_chars' => 420,
```

Если частей несколько, к ним добавляется номер:

```text
[1/3]
...

[2/3]
...
```

После успешной отправки каждой части индекс сохраняется в базе. При ошибке следующий цикл опроса продолжит с недоставленной части, а уже отправленные части не повторяются.

`reply_chunk_chars` — ограничение прикладного текста, а не точный расчёт PDU/GSM-7. Фактическое число сегментов у мобильного оператора может отличаться для Unicode и специальных символов.

## 11. Состояния истории команд

Актуально используются:

```text
processing
completed
failed
```

`queued` остаётся в схеме для совместимости со старыми установками, но отдельной очереди выполнения в Huawei SMS нет.

Дополнительный `result_status` описывает итог подробнее, например:

```text
completed
failed
timeout
output_limited
uncertain
recovered
```

## 12. Журнал команд

Аудит хранится в:

```text
logs/commands.log
```

Формат — JSON Lines: одна JSON-запись на строку.

В зависимости от параметров команды журнал может содержать:

- время;
- `request_id`;
- отпечаток;
- маскированный номер;
- имя команды;
- использованный алиас;
- аргументы;
- фактически переданные обработчику аргументы;
- тип обработчика;
- путь скрипта;
- итог;
- код завершения;
- длительность;
- признаки таймаута и превышения вывода;
- ответ;
- поток ошибок (`stderr`).

`log_arguments=false` скрывает аргументы.

`log_output=false` скрывает и стандартный вывод (`stdout`), и поток ошибок (`stderr`).

## 13. Проверка команды без SMS

Зарегистрированную команду можно запустить из консоли:

```bash
sudo -u www-data php /srv/huawei-sms/bin/script-command-test.php \
  пинг example.org
```

Для пользовательского плагина:

```bash
sudo -u www-data php /srv/huawei-sms/bin/script-command-test.php \
  статус
```

Команда проходит тот же разбор, проверку аргументов и запуск обработчика, что и реальное SMS. При этом запись в `sms_command_history` не создаётся и SMS не отправляется.

## 14. Порядок команд и локального списка блокировки

Для доверенного номера сначала проверяется механизм команд.

Поэтому известная SMS-команда с доверенного номера обрабатывается как команда до обычного локального списка блокировки.

Не используйте `trusted_phones` для номеров, которым вы не готовы разрешить зарегистрированные действия.
