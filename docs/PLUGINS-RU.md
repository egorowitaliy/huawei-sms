# Пользовательские SMS-команды

Huawei SMS умеет запускать собственные Bash- и Python-скрипты по SMS с доверенного телефона. Для этого не нужно изменять PHP-код проекта.

Пользовательская команда состоит из двух частей:

```text
commands.local.php       описание команды и ограничений
scripts.local/           сам Bash- или Python-обработчик
```

Например:

```text
SMS: Статус
    ↓
команда найдена в commands.local.php
    ↓
scripts.local/status.sh
    ↓
стандартный вывод (`stdout`)
    ↓
ответ по SMS
```

Это основной способ расширения Huawei SMS.

## 1. С чего начать

`commands.local.php` **дополняет** штатные `Пинг`, `Порт` и `Модем`. Копировать стандартные команды в локальный файл не нужно.

Начните с готового примера:

```bash
cp /srv/huawei-sms/commands.local.php.example \
  /srv/huawei-sms/commands.local.php
mcedit /srv/huawei-sms/commands.local.php
```

Добавляйте в него только свои команды. Если локальная запись использует то же `script_command`, что и штатная, она заменит только эту конкретную запись. Это позволяет при необходимости переопределить штатный обработчик и сохраняет совместимость со старыми локальными конфигурациями.

Обработчики размещайте в:

```text
/srv/huawei-sms/scripts.local/
```

Комплектный `scripts/` лучше не менять: он относится к ядру и может быть заменён при обновлении.


### Быстрая проверка на комплектном примере

Скопируйте пример обработчика:

```bash
install -o root -g root -m 0755 \
  /srv/huawei-sms/examples/plugins/status.sh \
  /srv/huawei-sms/scripts.local/status.sh
```

Откройте локальный реестр:

```bash
mcedit /srv/huawei-sms/commands.local.php
```

и добавьте запись из:

```text
examples/plugins/commands-entry.php.example
```

После сохранения проверьте команду от того же пользователя, от которого работает `cron/poll.php`:

```bash
runuser -u www-data -- \
  php /srv/huawei-sms/bin/script-command-test.php статус
```

Если всё настроено правильно, в терминале появится тот же текст, который затем вернётся ответным SMS.

## 2. Самый простой обработчик

Файл:

```text
scripts.local/status.sh
```

```bash
#!/bin/bash
set -u

echo "СЕРВЕР"
echo "Имя: $(hostname)"
echo "Время работы: $(uptime -p)"
```

Права:

```bash
chown root:root /srv/huawei-sms/scripts.local/status.sh
chmod 0755 /srv/huawei-sms/scripts.local/status.sh
```

Запись в `commands.local.php`:

```php
[
    'script_command' => 'status',
    'aliases' => ['статус'],
    'description' => 'краткое состояние сервера',
    'usage' => 'Статус',
    'script_path' => __DIR__ . '/scripts.local/status.sh',
    'type' => 'bash',
    'enabled' => true,
    'timeout' => 15,
    'min_args' => 0,
    'max_args' => 0,
    'max_arg_chars' => 1,
    'max_output_bytes' => 4096,
    'max_reply_chars' => 1000,
    'log_arguments' => false,
    'log_output' => true,
],
```

После этого SMS:

```text
Статус
```

запустит обработчик через `/bin/bash`, а текст из его стандартного вывода станет ответом.

Готовые файлы примера:

```text
examples/plugins/status.sh
examples/plugins/commands-entry.php.example
```

## 3. Поддерживаемые типы

В версии 1.0.0 поддерживаются только:

```php
'type' => 'bash'
```

через `/bin/bash` и:

```php
'type' => 'python3'
```

через `/usr/bin/python3`.

Huawei SMS не собирает из SMS строку для `sh -c` или `bash -c`. Интерпретатор, путь к файлу и каждый аргумент передаются процессу отдельно.

Это значит, что пользовательский текст не должен превращаться в дополнительную команду оболочки через `;`, `|`, `$()` и похожие конструкции. Кроме раздельной передачи аргументов ядро выполняет их собственную проверку.

## 4. Имя и варианты вызова

Каноническое внутреннее имя:

```php
'script_command' => 'status',
```

должно:

- состоять из латинских букв нижнего регистра, цифр, `_` или `-`;
- начинаться с буквы или цифры;
- иметь длину не больше 32 символов.

Варианты, которые можно написать в SMS:

```php
'aliases' => ['статус', 'status'],
```

Регистр не учитывается. Каноническое `script_command` тоже автоматически является допустимым вариантом вызова.

Служебные имена, занятые ядром, использовать нельзя.

## 5. Описание и подсказка

```php
'description' => 'краткое состояние сервера',
'usage' => 'Статус',
```

`description` попадает в список доступных команд.

`usage` добавляется к ответу при неправильных аргументах. Можно указать несколько строк:

```php
'usage' => "Проверка <имя>\nПроверка <имя> <порт>",
```

## 6. Как разбираются аргументы

Текст SMS делится по пробельным символам.

Сообщение:

```text
Проверка server.example.org 443
```

даёт два пользовательских аргумента:

```text
server.example.org
443
```

В Bash:

```text
$1 = server.example.org
$2 = 443
```

В Python:

```python
sys.argv[1] == "server.example.org"
sys.argv[2] == "443"
```

Кавычки **не объединяют** несколько слов в один аргумент. SMS:

```text
Команда "hello world"
```

не передаст `hello world` одной строкой. Парсер всё равно разделит текст по пробелу, а кавычки затем будут отвергнуты стандартной фильтрацией.

Если скрипту нужен произвольный текст с пробелами, текущая система аргументов для этого не предназначена. Надёжнее использовать короткие идентификаторы или заранее разрешённые значения.

## 7. Количество и размер аргументов

Пример:

```php
'min_args' => 1,
'max_args' => 2,
'max_arg_chars' => 128,
'max_total_arg_bytes' => 2048,
```

Пределы ядра:

| Параметр | Диапазон |
| --- | ---: |
| `min_args` | 0–32 |
| `max_args` | до 32 |
| `max_arg_chars` | 1–512 символов |
| `max_total_arg_bytes` | 64–8192 байт |

Каждый аргумент должен быть непустой корректной UTF-8 строкой без управляющих символов.

## 8. Фильтрация аргументов

После проверки длины каждый аргумент проверяется регулярным выражением.

Стандартный шаблон разрешает буквы, цифры и:

```text
. _ : @ + = , -
```

По умолчанию запрещены, в частности:

```text
; & | $ ` \ кавычки скобки пробелы /
```

Общий собственный шаблон:

```php
'argument_pattern' => '/\A[a-z0-9.-]+\z/i',
```

Разные шаблоны по позициям:

```php
'argument_patterns' => [
    0 => '/\A[a-z0-9][a-z0-9.-]{0,252}\z/i',
    1 => '/\A[0-9]{1,5}\z/',
],
```

Позиции считаются с нуля.

Не используйте без необходимости шаблон вроде `/.*/`. Это граница между внешним SMS и локальной системой.

## 9. Алиасы значений аргумента

Можно разрешить пользователю русские слова, а скрипту передавать только заранее определённые латинские значения:

```php
'argument_aliases' => [
    0 => [
        'start' => ['start', 'старт', 'запуск'],
        'stop' => ['stop', 'стоп', 'остановка'],
    ],
],
```

SMS `Сервис остановка` передаст скрипту `stop`.

Каноническое значение слева должно быть безопасным латинским токеном. Это удобнее и безопаснее, чем разрешать обработчику произвольный текст.

## 10. Один обработчик для нескольких команд

`alias_prefix_args` позволяет разным вариантам SMS-команды автоматически добавлять аргумент перед пользовательскими.

Так устроены штатные `Пинг` и `Порт`.

Упрощённо:

```php
[
    'script_command' => 'network',
    'aliases' => ['пинг', 'порт'],
    'alias_prefix_args' => [
        'пинг' => ['ping'],
        'порт' => ['port'],
    ],
],
```

Тогда:

```text
Пинг example.org
```

даёт обработчику:

```text
ping example.org
```

а:

```text
Порт example.org 443
```

даёт:

```text
port example.org 443
```

Автоматически добавляемые значения тоже обязаны быть безопасными латинскими токенами.

## 11. Полный пример с аргументом

Допустим, нужно получать состояние одной из двух заранее известных служб.

Запись в `commands.local.php`:

```php
[
    'script_command' => 'service',
    'aliases' => ['сервис'],
    'description' => 'состояние выбранной службы',
    'usage' => 'Сервис <web|db>',
    'script_path' => __DIR__ . '/scripts.local/service-status.sh',
    'type' => 'bash',
    'enabled' => true,
    'timeout' => 10,

    'min_args' => 1,
    'max_args' => 1,
    'max_arg_chars' => 16,
    'max_total_arg_bytes' => 64,

    'argument_aliases' => [
        0 => [
            'web' => ['web', 'веб'],
            'db' => ['db', 'база'],
        ],
    ],
    'argument_patterns' => [
        0 => '/\A(?:web|db)\z/',
    ],

    'max_output_bytes' => 4096,
    'max_reply_chars' => 700,
    'log_arguments' => true,
    'log_output' => true,
],
```

Обработчик:

```bash
#!/bin/bash
set -Eeuo pipefail

case "${1:-}" in
    web)
        systemctl is-active nginx
        ;;
    db)
        systemctl is-active postgresql
        ;;
    *)
        echo "Неизвестная служба"
        exit 2
        ;;
esac
```

Права:

```bash
chown root:root /srv/huawei-sms/scripts.local/service-status.sh
chmod 0755 /srv/huawei-sms/scripts.local/service-status.sh
```

## 12. Python-обработчик

Пример `scripts.local/check.py`:

```python
#!/usr/bin/env python3

import sys

if len(sys.argv) != 2:
    print("Нужен один аргумент")
    raise SystemExit(2)

print(f"Проверено: {sys.argv[1]}")
```

Запись:

```php
[
    'script_command' => 'check',
    'aliases' => ['проверка'],
    'description' => 'пример Python-обработчика',
    'usage' => 'Проверка <имя>',
    'script_path' => __DIR__ . '/scripts.local/check.py',
    'type' => 'python3',
    'enabled' => true,
    'timeout' => 10,
    'min_args' => 1,
    'max_args' => 1,
    'max_arg_chars' => 64,
    'max_total_arg_bytes' => 128,
    'argument_pattern' => '/\A[a-z0-9._-]+\z/i',
    'max_output_bytes' => 4096,
    'max_reply_chars' => 700,
    'log_arguments' => true,
    'log_output' => true,
],
```

## 13. Что становится ответом по SMS

Обработчик пишет пользовательский ответ в стандартный вывод.

Bash:

```bash
echo "Сервис работает"
```

Python:

```python
print("Сервис работает")
```

При коде завершения `0`:

- непустой `stdout` становится ответом;
- пустой `stdout` превращается в `Команда выполнена успешно`.

При ненулевом коде:

- непустой `stdout` становится текстом ошибки;
- при пустом `stdout` Huawei SMS возвращает общее сообщение и код завершения.

`stderr` пользователю по SMS не отправляется.

Если пользователь должен увидеть конкретную причину ошибки, напишите её в `stdout` и завершите процесс ненулевым кодом:

```bash
if ! test -f /srv/example/state; then
    echo "Состояние недоступно"
    exit 2
fi
```

## 14. Ограничение вывода

```php
'max_output_bytes' => 4096,
'max_reply_chars' => 1000,
```

`max_output_bytes` ограничивает общий объём `stdout` и `stderr`. Реальный диапазон — от 1024 до 65536 байт.

Если предел превышен, процесс завершается.

`max_reply_chars` ограничивает итоговый ответ до деления на SMS. Реальный диапазон — от 70 до 4000 символов.

Слишком длинный ответ сокращается с пометкой:

```text
[сокращено]
```

SMS не подходит для больших отчётов. Лучше возвращать короткий итог.

## 15. Время выполнения

```php
'timeout' => 15,
```

Допустимо от 1 до 300 секунд.

`bin/command-runner.py` создаёт отдельную группу процессов. При таймауте Huawei SMS завершает не только основной Bash/Python-процесс, но и запущенные им дочерние процессы.

Не используйте `nohup`, `&` и похожие обходы для оставления фоновых процессов. Если действие должно жить отдельно, передавайте запрос штатной внешней службе или через файл-заявку.

## 16. Одновременный запуск

Внешние SMS-команды выполняются последовательно.

Общая блокировка:

```text
data/script-commands.lock
```

не даёт двум обработчикам работать одновременно.

Если вашему скрипту нужна дополнительная защита конкретного ресурса, добавьте её внутри самого обработчика.

## 17. Переменные окружения

Обработчик получает предсказуемое очищенное окружение.

| Переменная | Значение |
| --- | --- |
| `SMS_PHONE` | нормализованный номер отправителя с `+` |
| `SMS_COMMAND` | каноническое имя |
| `SMS_COMMAND_ALIAS` | вариант, написанный в SMS |
| `SMS_REQUEST_ID` | идентификатор конкретного запуска |
| `SMS_FINGERPRINT` | отпечаток исходного SMS |
| `SMS_RECEIVED_AT` | время запуска ISO 8601 |
| `MODEM_URL` | адрес Huawei |
| `MODEM_TIMEOUT` | таймаут Huawei API |
| `MODEM_LOCK_FILE` | общая блокировка Huawei API |

Также задаются:

```text
LC_ALL=C.UTF-8
LANG=C.UTF-8
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
HOME=/nonexistent
TMPDIR=/tmp
PYTHONIOENCODING=UTF-8
PYTHONUNBUFFERED=1
```

Пример:

```bash
echo "Команда: ${SMS_COMMAND}"
echo "Отправитель: ${SMS_PHONE}"
```

Эти значения не являются секретным хранилищем.

## 18. Обращение к Huawei из своего скрипта

`MODEM_URL`, `MODEM_TIMEOUT` и `MODEM_LOCK_FILE` передаются специально для обработчиков, которым нужен тот же модем.

Если плагин сам обращается к Huawei API, он должен учитывать `MODEM_LOCK_FILE`, чтобы не пересекаться с основным опросом.

Комплектный `scripts/modem-health.sh` можно использовать как пример.

Не зашивайте адрес модема в собственный скрипт, если он уже доступен через `MODEM_URL`.

## 19. Права на обработчики

Перед запуском ядро проверяет файл.

Обработчик должен:

- находиться внутри `scripts/` или `scripts.local/`;
- быть обычным файлом;
- не быть символической ссылкой;
- принадлежать `root`;
- не иметь права записи для группы и остальных;
- находиться в каталогах под владельцем `root`, которые также не доступны на запись группе и остальным;
- не иметь `setuid` или `setgid`;
- быть доступным для чтения пользователю PHP.

Нормальный вариант:

```bash
chown root:www-data /srv/huawei-sms/scripts.local
chmod 0755 /srv/huawei-sms/scripts.local
chown root:root /srv/huawei-sms/scripts.local/status.sh
chmod 0755 /srv/huawei-sms/scripts.local/status.sh
```

Если используются вложенные каталоги внутри `scripts.local/`, для них действует то же правило: владелец `root`, запись для группы и остальных пользователей запрещена.

Такие же требования безопасности применяются к `bin/command-runner.py` и каталогу `bin/`.

## 20. Почему PHP не должен работать от root

По умолчанию Huawei SMS запрещает запуск внешнего обработчика, если сам PHP-процесс имеет UID 0.

Обычная схема:

```text
root              владеет кодом и обработчиками
www-data          запускает PHP-FPM и cron/poll.php
```

Это не даёт ошибке в SMS-плагине автоматически превратиться в удалённую команду с правами root.

Существует явное исключение:

```php
'allow_root_execution' => true,
```

но включать его без реальной необходимости не следует.

## 21. SSH-ключи и секреты

Сам Bash/Python-файл должен принадлежать `root`, но приватный SSH-ключ обычно должен принадлежать пользователю, от которого реально запускается процесс, и иметь права не шире `0600`.

Пример:

```text
script:
root:root 0755

private key:
sms-user:sms-user 0600
```

Не храните рабочие ключи внутри публичного `scripts.local/`.

Для локальных закрытых данных предусмотрен каталог:

```text
secrets/
```

Конкретные права зависят от пользователя PHP и задачи.

## 22. Аудит выполнения

Аудит внешних команд:

```text
logs/commands.log
```

Формат — одна JSON-запись на строку.

Основные настройки:

```php
'log_arguments' => true,
'log_output' => true,
```

`log_arguments=false` скрывает аргументы.

Если журналировать можно не всё:

```php
'redact_args' => [1, 2],
```

Позиции считаются с нуля.

`log_output=false` скрывает из аудита и итоговый ответ, и `stderr`.

Пароли и токены вообще лучше не передавать в SMS. Если чувствительный аргумент неизбежен, отключите его журналирование.

## 23. Обязательный аудит до запуска

```php
'audit_required' => true,
```

требует успешно записать событие начала выполнения до запуска скрипта.

Если журнал недоступен, команда не выполняется.

Для команды, меняющей состояние инфраструктуры, это разумная настройка. Для простой диагностики параметр можно не задавать.

## 24. Ответ после успеха

По умолчанию успешный результат отправляется по SMS.

Параметр:

```php
'reply_on_success' => false,
```

позволяет не отправлять успешный ответ. Ошибки при этом могут быть возвращены.

## 25. Повторная доставка одного SMS

Для исходного сообщения вычисляется устойчивый отпечаток, а состояние команды хранится в SQLite.

Уже завершённая команда повторно не запускается.

Если процесс оборвался в состоянии `processing`, внешняя команда после истечения срока **не запускается автоматически ещё раз**. Ядро не знает, успел ли скрипт изменить реальную систему до аварии, поэтому повторное действие могло бы быть опасным.

Повторяется только доставка уже подготовленного ответа, если она временно не удалась.

## 26. Длинные ответы

Большой ответ делится на части:

```text
[1/3]
...
```

Состояние отправки частей хранится в SQLite.

Если первые две части ушли, а третья нет, следующий цикл продолжит с третьей. Уже доставленные части повторно не отправляются.

## 27. Полный список параметров

| Параметр | Назначение |
| --- | --- |
| `script_command` | каноническое латинское имя |
| `aliases` | варианты команды в SMS |
| `description` | описание в списке команд |
| `usage` | подсказка по синтаксису |
| `script_path` | путь к обработчику |
| `type` | `bash` или `python3` |
| `enabled` | включена ли команда |
| `timeout` | время выполнения, 1–300 секунд |
| `min_args` | минимальное число аргументов |
| `max_args` | максимальное число аргументов, до 32 |
| `max_arg_chars` | длина одного аргумента |
| `max_total_arg_bytes` | общий размер аргументов |
| `argument_pattern` | общий шаблон допустимого аргумента |
| `argument_patterns` | шаблоны отдельных позиций |
| `argument_aliases` | разрешённые слова → канонические значения |
| `alias_prefix_args` | автоматические аргументы для варианта команды |
| `max_output_bytes` | предел общего `stdout` + `stderr` |
| `max_reply_chars` | предел итогового текста |
| `log_arguments` | писать ли аргументы в аудит |
| `redact_args` | позиции аргументов, которые надо скрыть |
| `log_output` | писать ли результат и `stderr` |
| `audit_required` | требовать аудит до запуска |
| `reply_on_success` | отправлять ли успешный ответ |
| `allow_root_execution` | разрешить выполнение при PHP от root |

Для простой команды не нужно указывать все параметры. Задавайте только нужное и оставляйте ограничения максимально узкими.

## 28. Проверка до реального SMS

Общая проверка установки:

```bash
runuser -u www-data -- php /srv/huawei-sms/bin/preflight.php
```

Проверка отдельного обработчика:

```bash
runuser -u www-data -- php /srv/huawei-sms/bin/script-command-test.php
```

Запуск без необходимых аргументов покажет формат команды.

После теста можно посмотреть аудит:

```bash
tail -n 20 /srv/huawei-sms/logs/commands.log
```

## 29. Привилегированные действия

Публичное ядро не содержит готовой команды перезагрузки физического сервера, управления PDU, гипервизором, АТС или другой конкретной инфраструктурой.

Такое действие лучше подключать как локальный обработчик и не давать самому Huawei SMS права root.

Например:

```text
SMS «Перезагрузка»
        ↓
scripts.local/request-host-reboot.sh
        ↓
создание строго определённого файла-заявки
        ↓
отдельная служба с правами root
        ↓
проверка заявки
        ↓
перезагрузка системы
```

Так SMS-приложение только создаёт запрос, а привилегированное действие выполняет отдельный небольшой механизм.

Готовый плагин перезагрузки системы специально не входит в публичный проект.

## 30. Практические правила

Хороший обработчик:

- решает одну понятную задачу;
- принимает минимальный набор аргументов;
- разрешает только ожидаемые значения;
- не строит команду оболочки из пользовательского текста;
- имеет короткий таймаут;
- возвращает короткий понятный ответ;
- использует ненулевой код при ошибке;
- не пишет секреты в `stdout` и `stderr`;
- по возможности не требует root;
- для изменяющего действия сам проверяет исходное состояние;
- по возможности является идемпотентным.

Самый безопасный плагин — тот, которому не приходится доверять произвольный текст из SMS.
