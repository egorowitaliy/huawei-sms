# Архитектура Huawei SMS

Huawei SMS специально остаётся небольшим приложением без отдельного фонового демона, очереди сообщений и внешней СУБД.

Основная схема:

```text
Huawei HiLink
    │
    │ HTTP/XML API
    ▼
PHP
    ├── SQLite
    ├── веб-интерфейс
    ├── обработка SMS-команд
    ├── контроль доступности модема
    └── уведомления Telegram / MAX / Matrix
           │
           └── внешние HTTPS API

SMS-команда с доверенного номера
    │
    ▼
реестр команд
    │
    ▼
Bash или Python-обработчик
    │
    ▼
стандартный вывод скрипта → ответное SMS
```

## 1. Основные части проекта

### `public/`

Единственная часть, которую должен публиковать веб-сервер.

```text
public/index.php
public/assets/
```

`public/index.php` подключает общее ядро, запускает сессию, проверяет базу, авторизацию и только после этого показывает веб-интерфейс.

### `init.php`

Общая основа приложения:

- загрузка конфигурации;
- настройка сессии;
- подключение SQLite;
- создание и обновление схемы;
- работа с Huawei API;
- чтение и удаление SMS;
- отправка SMS;
- перенос сообщений из памяти модема в базу;
- состояние приложения в `app_state`.

### `auth.php`

Веб-авторизация:

- логин и пароль;
- ограничение неудачных попыток;
- сессия;
- CSRF;
- TOTP;
- события входа.

### `notify.php`

Каналы уведомлений:

- Telegram;
- MAX;
- Matrix;
- прокси Telegram/MAX;
- поканальное состояние доставки уведомлений о входящих SMS.

### `sms_commands.php`

Общий механизм SMS-команд:

- доверенные номера;
- HELP;
- отпечаток команды;
- история выполнения;
- разбиение ответа на части;
- повтор отправки недоставленного результата без повторного выполнения команды.

### `script_commands.php`

Механизм пользовательских Bash- и Python-команд:

- реестр команд;
- алиасы;
- разбор аргументов;
- ограничения;
- нормализация значений;
- проверка пути и прав обработчика;
- запуск через отдельный Python-wrapper;
- ограничение времени и размера вывода;
- аудит.

### `modem_monitor.php`

Состояние модема:

- счётчик последовательных ошибок;
- переход в состояние «недоступен»;
- подтверждённое восстановление;
- поканальные уведомления;
- режим обслуживания при плановой перезагрузке;
- плановая перезагрузка через Huawei API.

### `cron/poll.php`

Одноразовый цикл обслуживания.

Он запускается, выполняет одну попытку работы и завершается. Постоянно работающего процесса Huawei SMS не создаёт.

### `bin/`

Служебные команды администратора:

- `preflight.php` — проверка установленной системы;
- `migrate.php` — ручное открытие/обновление SQLite и проверка её состояния;
- `password-hash.php` — создание хеша пароля;
- `totp-secret.php` — создание TOTP-секрета;
- `script-command-test.php` — ручной запуск зарегистрированной SMS-команды без SMS;
- `test-notifications.php` — проверка канала уведомлений;
- `modem-monitor-status.php` — состояние автомата контроля модема;
- `command-runner.py` — безопасный запуск внешнего обработчика и управление его группой процессов.

## 2. Что происходит при каждом цикле опроса

Типичный запуск:

```text
systemd timer / cron
        │
        ▼
cron/poll.php
        │
        ├── повтор недоставленных системных уведомлений
        │
        ├── sync_sms_from_modem()
        │       │
        │       ├── повтор готовых ответов старых команд
        │       ├── входящие Huawei
        │       └── исходящие Huawei
        │
        ├── modem_monitor_mark_success()
        │
        └── modem_auto_reboot_tick()
```

Если обращение к модему заканчивается исключением, `poll.php` передаёт ошибку в `modem_monitor_mark_failure()` и завершается.

## 3. Почему сообщения читаются повторно с первой страницы

Huawei API возвращает SMS страницами. Huawei SMS запрашивает по 10 сообщений.

После обработки порции сообщения удаляются из памяти модема. Поэтому следующая первая страница уже содержит следующую порцию.

Алгоритм выглядит так:

```text
прочитать первую страницу
        ↓
обработать и удалить то, что можно удалить
        ↓
снова прочитать первую страницу
        ↓
...
```

Если в очередной порции не удалось удалить ни одного сообщения, цикл прерывается. Это защищает от бесконечного чтения одной и той же записи при ошибке Huawei.

Есть также защитный предел числа порций за один запуск.

## 4. Обработка входящего SMS

Для каждого входящего сообщения порядок такой:

```text
SMS
 │
 ├─ доверенный номер + известная команда?
 │      └─ выполнить механизм команды
 │
 ├─ запись попала в локальный список блокировки?
 │      └─ удалить как нежелательную и записать в spam.log
 │
 └─ обычное SMS
        └─ сохранить в SQLite и подготовить уведомление
```

Командное SMS тоже сохраняется в общей таблице `sms`, но для него не отправляется обычное уведомление «Новое SMS», потому что результат команды имеет собственный ответ.

Локальный список блокировки является осознанным исключением: нежелательное SMS в обычную историю не попадает.

## 5. Обработка исходящих SMS

SMS, отправленное через Huawei SMS, сразу записывается в SQLite.

Позже Huawei может показать свою копию того же сообщения в папке исходящих. Система пытается сопоставить её с уже сохранённой локальной записью по номеру, тексту и близкому времени отправки.

Если подходящая запись найдена, она связывается с индексом Huawei и после удаления из памяти модема помечается как удалённая.

Если исходящее SMS появилось на Huawei из другого источника, например из штатного веб-интерфейса модема, Huawei SMS создаёт для него новую запись в SQLite, а затем удаляет модемную копию.

## 6. Отпечатки сообщений

Для защиты от повторного импорта используется `source_fingerprint`.

Базовый отпечаток строится из направления, номера, даты SMS и текста.

Для SMS, которое только что отправлено самим Huawei SMS, `modem_index` ещё неизвестен. Такая локальная запись временно получает дополнительный случайный признак, поэтому две одинаковые отправки одному номеру в одну секунду не схлопываются в одну строку. После появления копии в папке исходящих Huawei запись связывается с индексом модема и получает обычный модемный отпечаток.

Индекс Huawei не используется как самостоятельный идентификатор, потому что после удаления старого сообщения модем может выдать тот же индекс другой записи. Если два физически разных SMS имеют одинаковые номер, дату и текст, индекс Huawei используется только как дополнительный признак, чтобы не потерять одно из них.

## 7. Командные SMS

Команды выполняются только с номеров из `trusted_phones`.

Порядок:

```text
номер отправителя
    ↓
нормализация
    ↓
проверка trusted_phones
    ↓
разбор первого слова SMS
    ↓
реестр штатных + локальных команд
    ↓
проверка аргументов
    ↓
запуск обработчика
    ↓
сохранение результата
    ↓
ответ по SMS
```

Перед запуском внешнего обработчика запись команды переводится в `processing`.

После завершения сохраняются итоговый статус и готовый текст ответа. Если отправка ответного SMS не удалась, следующий цикл опроса может повторить только отправку уже готового ответа.

Внешний обработчик повторно не запускается.

Если процесс Huawei SMS аварийно завершился во время внешней команды и позднее запись осталась в `processing`, ядро не может достоверно понять, успел ли скрипт выполнить действие. Поэтому после истечения защитного времени такая команда автоматически второй раз **не выполняется**. Пользователь получает сообщение о неопределённом результате.

HELP является безопасным исключением: он не выполняет внешних действий и может быть восстановлен после зависшего `processing`.

## 8. Пользовательские плагины

Штатные команды находятся в `config.php`.

Локальный файл:

```text
commands.local.php
```

дополняет этот список.

Если локальная запись использует тот же `script_command`, что и штатная, локальная версия заменяет конкретную штатную запись. Это позволяет при необходимости переопределить обработчик и сохраняет совместимость со старыми конфигурациями.

Обычный пользовательский код хранится в:

```text
scripts.local/
```

Ядро не сканирует этот каталог автоматически. Скрипт становится SMS-командой только после явной записи в `commands.local.php`.

## 9. Запуск внешнего обработчика

PHP не использует пользовательский текст SMS как команду оболочки.

Фактическая схема:

```text
PHP
 ↓
/usr/bin/python3 bin/command-runner.py
 ↓
/bin/bash scripts.local/example.sh arg1 arg2
```

или:

```text
/usr/bin/python3 scripts.local/example.py arg1 arg2
```

Каждый элемент передаётся отдельным аргументом процесса.

`command-runner.py` создаёт отдельную группу процессов. При превышении времени выполнения ядро завершает не только главный Bash/Python-процесс, но и его дочерние процессы.

## 10. Окружение плагина

Обработчик получает очищенное окружение с небольшим набором служебных переменных, включая сведения о команде и Huawei.

Обычное окружение PHP целиком наружу не передаётся. Это уменьшает вероятность случайно передать в пользовательский скрипт секреты среды веб-сервера.

Точный список описан в [PLUGINS-RU.md](PLUGINS-RU.md).

## 11. SQLite

`db()` является единственным источником актуальной схемы.

Отдельного `database/schema.sql` нет намеренно: два независимых описания схемы быстро начинают расходиться.

При первом открытии чистой базы создаются необходимые таблицы, индексы и `PRAGMA user_version = 5`.

При открытии старой базы код добавляет недостающие поля и выполняет встроенные преобразования.

Если база имеет `user_version` больше поддерживаемого, Huawei SMS прекращает работу с ошибкой. Старый код не пытается открыть будущую схему как свою и не понижает её маркер.

## 12. Параллельная работа

SQLite работает в WAL-режиме с `busy_timeout`.

Дополнительно используются файловые блокировки:

- `sync.lock` — не допускает два одновременных переноса SMS;
- `modem-api.lock` — сериализует изменяющие POST-запросы к Huawei;
- `script-commands.lock` — не допускает параллельное выполнение внешних SMS-команд.

Это важно, потому что веб-интерфейс и `cron/poll.php` могут работать одновременно.

## 13. Контроль доступности модема

Успехом автомата считается успешное завершение основного цикла `cron/poll.php`, а не открытие страницы статуса и не ручная команда `Модем`.

После нескольких последовательных ошибок модем получает состояние «недоступен» (`offline`).

После нескольких последовательных успешных циклов опроса — состояние «доступен» (`online`).

Счётчики и состояние хранятся в `app_state`, поэтому перезапуск PHP или systemd их не сбрасывает.

Уведомления о недоступности и восстановлении имеют отдельное состояние по каждому включённому каналу. Если Telegram доставил событие, а Matrix нет, повторная попытка выполняется только для недоставленного канала.

## 14. Плановая перезагрузка Huawei

Плановая перезагрузка вызывается из `cron/poll.php` после успешной синхронизации.

Отдельное периодическое задание для перезагрузки не нужно.

Перед POST-запросом Huawei SMS:

- проверяет день недели и временное окно;
- проверяет, не было ли уже попытки в этот день;
- записывает попытку в `app_state`;
- включает режим обслуживания;
- при необходимости отправляет уведомление о начале.

Метка попытки ставится **до** запроса на перезагрузку. Если Huawei успеет перезагрузиться и оборвёт HTTP-соединение раньше ответа, система не станет повторять опасную команду в том же окне.

Во время `maintenance_seconds` ошибки API не переводят обычный контроль доступности в состояние «недоступен».

Первый успешный цикл опроса после перезагрузки завершает режим обслуживания и формирует уведомление об успешном восстановлении.

Если обслуживание истекло, а Huawei не вернулся, сохраняется неуспешный результат и затем продолжается обычная логика контроля недоступности.

## 15. Уведомления

Включённые каналы определяются независимо.

Для входящих SMS состояние доставки хранится в таблице `sms_notification_deliveries`.

Для событий модема состояние отдельных каналов хранится в `app_state`.

Telegram и MAX могут использовать прокси. Matrix в версии 1.0.0 работает напрямую.

Прямой резервный путь при `fallback_direct=true` используется только когда запрос через прокси не дошёл до нормального ответа удалённого API. HTTP-ошибка самого сервиса не обходится прямым соединением.

## 16. Что является локальной частью установки

Ядро не должно содержать сведения о конкретной организации или сервере.

Локальные различия находятся только в:

```text
config.local.php
commands.local.php
blocklist.local.php
scripts.local/
secrets/
```

и в конфигурации nginx, PHP-FPM, systemd или cron конкретного сервера.

Так один и тот же выпуск Huawei SMS можно использовать на разных площадках без форков PHP-кода.
