# Обновление Huawei SMS

Huawei SMS хранит рабочие данные отдельно от кода. Обновление лучше готовить в новом каталоге, а рабочую установку переключать только после проверки нового выпуска.

## Что нужно сохранить

Локальными данными конкретной установки являются:

```text
config.local.php
commands.local.php
blocklist.local.php
data/sms.sqlite
secrets/
scripts.local/
```

Каталог `logs/` для восстановления не обязателен, но его можно сохранить для диагностики.

Не переносите из старого выпуска файлы ядра вместо файлов нового выпуска. Если в новой версии изменился пример конфигурации, сравните его со своей локальной настройкой и перенесите только действительно нужные параметры.

## 1. Подготовьте новый выпуск

Распакуйте архив в отдельный пустой каталог:

```bash
mkdir -p /srv/huawei-sms-new
tar -xzf huawei-sms-1.0.0.tar.gz \
  --strip-components=1 \
  -C /srv/huawei-sms-new
```

Сравните новую конфигурацию со своей:

```bash
mcedit /srv/huawei-sms-new/config.local.php.example
mcedit /srv/huawei-sms/config.local.php
```

Если появились новые необязательные параметры, обычно добавлять их в `config.local.php` не требуется: значения по умолчанию находятся в `config.php`.

## 2. Остановите изменение рабочих данных

Перед окончательным снимком базы остановите периодический опрос и временно исключите запись в Huawei SMS через веб-интерфейс.

Для systemd:

```bash
systemctl stop huawei-sms-poll.timer
systemctl status huawei-sms-poll.service --no-pager
```

Если используется cron, временно отключите соответствующее задание.

На время переключения закройте доступ к сайту Huawei SMS или остановите только тот контейнер, службу либо отдельный пул PHP-FPM, который обслуживает эту установку. Если один PHP-FPM используется несколькими сайтами, останавливать его целиком не требуется — достаточно временно закрыть именно Huawei SMS на уровне веб-сервера.

Убедитесь, что в этот момент не выполняются ручная синхронизация или пользовательская SMS-команда.

## 3. Сделайте согласованную резервную копию SQLite

Huawei SMS использует SQLite в режиме WAL. Не копируйте один работающий файл `data/sms.sqlite` обычной командой `cp`.

Создайте согласованный снимок средствами SQLite:

```bash
mkdir -p /root/huawei-sms-backup
chmod 0700 /root/huawei-sms-backup
sqlite3 /srv/huawei-sms/data/sms.sqlite \
  ".backup '/root/huawei-sms-backup/sms.sqlite'"
chmod 0600 /root/huawei-sms-backup/sms.sqlite
```

Проверьте снимок:

```bash
sqlite3 /root/huawei-sms-backup/sms.sqlite 'PRAGMA integrity_check;'
sqlite3 /root/huawei-sms-backup/sms.sqlite 'PRAGMA foreign_key_check;'
```

Первая команда должна вывести:

```text
ok
```

Вторая при исправной базе ничего не выводит.

Сохраните также локальные файлы конфигурации, `scripts.local/` и `secrets/`.

## 4. Перенесите локальную конфигурацию и плагины

Скопируйте в новый каталог:

```text
config.local.php
commands.local.php
blocklist.local.php
secrets/
scripts.local/
```

Не переносите старый каталог `data/` поверх нового во время работы приложения. Для новой установки используйте проверенный снимок базы из предыдущего шага.

Подготовьте каталог данных и восстановите снимок:

```bash
install -d -o www-data -g www-data -m 0750 /srv/huawei-sms-new/data
install -o www-data -g www-data -m 0640 \
  /root/huawei-sms-backup/sms.sqlite \
  /srv/huawei-sms-new/data/sms.sqlite
```

Если Huawei SMS работает не от `www-data`, укажите своего рабочего пользователя и группу.

Каталог журналов также должен быть доступен для записи рабочему пользователю:

```bash
install -d -o www-data -g www-data -m 0750 /srv/huawei-sms-new/logs
```

Проверьте права локальных обработчиков. Файлы плагинов должны принадлежать `root`, а каталоги на пути к ним не должны быть доступны на запись группе или остальным пользователям.

`commands.local.php` дополняет штатные команды. Если локальный файл содержит запись с тем же `script_command`, что и штатная команда, локальная запись заменяет штатную.

## 5. Проверьте новый каталог

Запустите предварительную проверку от рабочего пользователя:

```bash
sudo -u www-data php /srv/huawei-sms-new/bin/preflight.php
```

`preflight` откроет SQLite и при необходимости применит встроенные изменения схемы. Отдельный `schema.sql` для обновления не используется.

После этого можно отдельно проверить миграцию:

```bash
sudo -u www-data php /srv/huawei-sms-new/bin/migrate.php
```

Если база имеет более новый `PRAGMA user_version`, чем понимает текущий выпуск, программа завершит работу с ошибкой и не станет понижать версию схемы.

## 6. Переключите рабочий каталог

Когда проверки завершены, замените рабочий каталог способом, принятым в вашей инфраструктуре. Старый каталог не удаляйте, пока не проверите новый выпуск.

После переключения ещё раз выполните:

```bash
sudo -u www-data php /srv/huawei-sms/bin/preflight.php
```

Откройте веб-интерфейс и убедитесь, что история сообщений и состояние модема отображаются корректно.

## 7. Верните периодический опрос

Для systemd:

```bash
systemctl daemon-reload
systemctl start huawei-sms-poll.timer
systemctl status huawei-sms-poll.timer --no-pager
```

Проверьте последний запуск:

```bash
journalctl -u huawei-sms-poll.service -n 100 --no-pager
```

Состояние мониторинга модема можно посмотреть так:

```bash
sudo -u www-data php /srv/huawei-sms/bin/modem-monitor-status.php
```

После проверки снова откройте обычный доступ к веб-интерфейсу.

## Если обновление не удалось

1. снова остановите периодический опрос и запись через веб-интерфейс;
2. верните предыдущий код;
3. если новая версия уже изменила схему и старый код с ней несовместим, восстановите сохранённый снимок SQLite;
4. верните локальные файлы конфигурации, `scripts.local/` и `secrets/`;
5. выполните `preflight` предыдущей версии;
6. только после успешной проверки снова включите веб-интерфейс и периодический опрос.

Резервная копия перед обновлением обязательна даже при небольшом изменении кода.
