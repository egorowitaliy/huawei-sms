# Безопасная эксплуатация Huawei SMS

Huawei SMS принимает сообщения из мобильной сети, умеет отправлять SMS и может запускать локальные Bash- и Python-скрипты. Поэтому безопасность установки зависит не только от веб-интерфейса, но и от того, какие команды администратор разрешил выполнять по SMS.

## Основные правила

- публикуйте через веб-сервер только каталог `public/`;
- не размещайте `config.local.php`, `commands.local.php`, `data/`, `logs/`, `secrets/` и `scripts.local/` внутри открытого веб-каталога;
- не храните пароль веб-интерфейса открытым текстом — используйте `password_hash`;
- включайте TOTP для интерфейса, доступного извне;
- добавляйте в `trusted_phones` только реальные номера, с которых разрешено выполнение команд;
- пользовательские обработчики держите под владельцем `root` и не разрешайте запись в них рабочему пользователю PHP;
- не запускайте `cron/poll.php` от root без реальной необходимости;
- не включайте `allow_root_execution` у пользовательской команды просто для удобства;
- секреты Telegram, MAX, Matrix и прокси не публикуйте в Git;
- перед публикацией архива проверяйте, что в нём нет рабочей SQLite, журналов и локальных файлов конфигурации.

## Веб-сервер

Рекомендуемый корень сайта:

```text
/srv/huawei-sms/public
```

Файл `deploy-examples/nginx/huawei-sms.conf.example` разрешает выполнение только `public/index.php`, а остальные запросы к `.php` возвращают 404.

Если используется другой веб-сервер, нужно сохранить тот же принцип: весь проект не должен становиться доступным по HTTP.

## HTTPS

Для внешнего доступа используйте HTTPS.

Если TLS завершается на обратном прокси, его адрес нужно явно добавить в:

```php
'trusted_proxies' => [
    '127.0.0.1',
],
```

Только от доверенного прокси Huawei SMS принимает `X-Forwarded-Proto`, `X-Real-IP` и `X-Forwarded-For` как служебные заголовки.

`force_secure_cookie=true` принудительно включает флаг Secure у сессионной cookie.

## Пароль

Пароль хранится только в виде хеша:

```php
'auth' => [
    'enabled' => true,
    'username' => 'admin',
    'password_hash' => '...',
],
```

Создать хеш:

```bash
cd /srv/huawei-sms
read -rsp 'Пароль: ' P; echo
HUAWEI_SMS_PASSWORD="$P" php bin/password-hash.php
unset P
```

При наличии Argon2id используется он, иначе bcrypt.

## Защита входа

Huawei SMS:

- ведёт счётчик неудачных попыток по IP;
- временно блокирует вход после заданного числа ошибок;
- не теряет счётчик при двух параллельных запросах;
- использует CSRF-токен для изменяющих запросов;
- ограничивает частоту уведомлений об ошибках CSRF;
- сообщает о включении блокировки один раз, а не на каждый последующий запрос во время блокировки;
- завершает неактивную сессию по настроенному времени.

## TOTP

Секрет TOTP хранится в `config.local.php`, поэтому файл должен быть недоступен посторонним пользователям и веб-серверу.

Создать секрет:

```bash
php bin/totp-secret.php
```

Код проверяется в окне ±30 секунд. Один уже принятый временной код повторно использовать нельзя. Для корректной работы часы сервера должны быть синхронизированы.

`emergency_bypass` предназначен только для аварийного временного отключения второго фактора. Не оставляйте его включённым постоянно.

## SMS-команды

Команда выполняется только если:

1. механизм SMS-команд включён;
2. номер отправителя совпадает с одним из `trusted_phones`;
3. текст соответствует зарегистрированной команде;
4. аргументы проходят ограничения этой команды;
5. файл обработчика проходит проверки владельца и прав;
6. выполнение разрешено текущему пользователю PHP.

Huawei SMS не строит команду вида:

```text
bash -c "текст из SMS"
```

Путь к интерпретатору, путь к обработчику и каждый аргумент передаются процессу отдельно.

Это снижает риск внедрения команд через оболочку, но не делает небезопасный пользовательский скрипт безопасным автоматически. Если обработчик сам передаст аргумент в `eval`, `sh -c`, SQL-строку или другой интерпретатор без проверки, защита ядра не спасёт его.

Подробности: [docs/PLUGINS-RU.md](docs/PLUGINS-RU.md).

## Права пользовательских обработчиков

Файлы из `scripts/` и `scripts.local/`, которые запускаются как SMS-команды, должны:

- принадлежать UID 0 (`root`);
- не быть символьными ссылками;
- не иметь записи для группы или остальных пользователей;
- не иметь `setuid` или `setgid`;
- находиться внутри разрешённых каталогов команд;
- находиться в каталогах под владельцем `root`, которые также недоступны на запись группе и остальным пользователям.

Рекомендуемый вариант:

```bash
chown root:www-data /srv/huawei-sms/scripts.local
chmod 0755 /srv/huawei-sms/scripts.local
chown root:root /srv/huawei-sms/scripts.local/example.sh
chmod 0755 /srv/huawei-sms/scripts.local/example.sh
```

Если скрипту достаточно чтения:

```bash
chmod 0555 /srv/huawei-sms/scripts.local/example.sh
```

## Запуск от root

По умолчанию пользовательские команды блокируются, если PHP сам запущен от root.

Параметр:

```php
'allow_root_execution' => true,
```

существует только для осознанных специальных случаев. Он не должен быть обычным способом настройки.

Безопаснее запускать `cron/poll.php` от отдельного непривилегированного пользователя, например `www-data`, а привилегированное действие выносить в отдельную службу с правами root, принимающую только строго определённые запросы.

## systemd и права плагинов

Пример systemd использует дополнительные ограничения процесса:

- `NoNewPrivileges=true`;
- `ProtectSystem=strict`;
- `ProtectHome=true`;
- запись разрешена только в `data/` и `logs/`.

Если локальному плагину действительно нужно записывать файл-заявку в другой каталог, добавьте этот конкретный каталог в `ReadWritePaths=`. Не снимайте `ProtectSystem` целиком без необходимости.

## Журналы команд

`logs/commands.log` может содержать:

- номер отправителя в маскированном виде;
- имя команды;
- аргументы, если `log_arguments=true`;
- результат, если `log_output=true`;
- код завершения и длительность выполнения.

Для команд, где аргументы или результат содержат чувствительные данные, используйте:

```php
'log_arguments' => false,
'log_output' => false,
```

При `log_output=false` не сохраняются ни стандартный вывод (`stdout`), ни поток ошибок (`stderr`) обработчика.

Для выборочного скрытия аргументов предусмотрен `redact_args`.

## Секреты уведомлений

Токены можно хранить прямо в `config.local.php`, но для рабочей установки удобнее отдельные файлы в `secrets/`.

Например:

```php
'bot_token_file' => __DIR__ . '/secrets/telegram-token',
```

Рекомендуемые права:

```bash
chown root:www-data /srv/huawei-sms/secrets/telegram-token
chmod 0640 /srv/huawei-sms/secrets/telegram-token
```

Сам каталог:

```bash
chown root:www-data /srv/huawei-sms/secrets
chmod 0750 /srv/huawei-sms/secrets
```

## Прокси

Пароль прокси не выводится штатным журналированием Huawei SMS.

Проверка TLS у Telegram, MAX и Matrix специально не отключается. Не добавляйте `CURLOPT_SSL_VERIFYPEER=false` ради обхода проблем с сертификатами — исправляйте цепочку доверия на сервере.

`fallback_direct=true` может раскрыть прямой сетевой маршрут к Telegram или MAX. Включайте его только там, где такой обход прокси действительно допустим политикой сети.

## SQLite

Рабочая база содержит SMS и историю выполнения команд. Она не должна быть доступна по HTTP или попадать в публичный Git.

Каталог `data/` должен быть доступен на запись только рабочему пользователю приложения и администраторам.

Для резервной копии работающей базы используйте согласованный снимок SQLite, а не обычное копирование одного файла при активном WAL.
